# Computer Use 会话恢复修复

## 原因

- 长生命周期 MCP 进程存活，不代表它的隐式 Cua 会话仍有效；多个 DSH 会话复用已结束的隐式会话。
- PiP 的后台策略把 `start_session`、会话查询及权限诊断当作未审查操作，阻断恢复入口。
- 窗口绑定工具的内部 AX 调用没有管理驱动会话，因而可能出现预览有画面、操作却失败。
- 菜单栏等没有普通应用窗口的目标无法声明桌面降级。
- 拼错的 `mcp__cua-driver-mcp__computer_pip` 被误报为策略拒绝，设置页则仅检查插件、进程及 TCC 状态。

## 已修复

1. `DriverSessions` 按 DSH 会话和 provider 分配独立标签。模型省略或传入历史标签均由 Host 映射；窗口绑定子调用使用相同标签。
2. 通过原有工具管线在非生命周期操作前调用一次幂等 `start_session`。只恢复动作前的生命周期，不重放已派发输入，不更换 provider；权限、撤销、审批和连接错误直接返回。
3. 显式 `end_session` 暂停该驱动会话，包括结束结果不确定的情况；必须显式重新开始。取消、卸载和会话销毁不会让待处理的预检继续派发输入。
4. 重定向保持原调用身份不可变，重新经过宿主审批和 guard；保留图片、附加上下文及结束轮次信号，不覆盖其他结果策略。
5. 受控放行生命周期及只读诊断；权限诊断显式使用 `prompt:false`，不通过生命周期授予桌面权限。
6. 新增 `controlScope:"desktop"`，用于菜单栏、托盘等系统界面，无需绑定无关窗口。仍限制独占、时限、轮次、取消、坐标范围，不放开驱动脚本和持续整屏录制。
7. Host 工具前缀错误会得到明确的工具名纠正提示；其他未知名称交由注册表返回未知工具。
8. 设置页通过现有 MCP 的 `list_windows` 探测真实调用链，返回 `driver.toolchain`；不采集图片或发送输入。探针合并并发请求，缓存五秒，失败会覆盖仅表示插件存活的运行状态。
