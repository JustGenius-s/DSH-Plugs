# @just-genius/dsh-workspace-plus

DSH 侧栏增强：**置顶区** + 官方行菜单的额外入口 + 多文件夹工作区 + 会话导出。

定位是**只在官方 UI 上加内容**：不接管官方 slot、不重排官方列表、不覆盖官方行为。
DSH 自己有的能力（会话置顶、行菜单的置顶/重命名/分叉/归档、归档过滤视图）
一律复用官方实现，插件不重复造。

## 置顶区

位于侧栏「工作区」标题**正下方**、跟着列表一起滚动的一块独立列表，**项目和会话都能置顶**：

- **项目置顶**：点官方项目行菜单（`…`）里的「置顶项目」。
- **会话置顶**：用官方会话行的「置顶会话」按钮或菜单 —— 与插件置顶区是**同一份数据**
  （DSH 的 `pinnedSessionIds`），所以两处永远不会不一致。
- **置顶项目是一个可展开的分组**，包含该工作区的**全部会话**（不只是被置顶的那几个）；
  **点行即展开 / 收起**，无需另找箭头。分组内**被置顶的会话排在最前**，其余按最近更新排序。
- 因此一个会话**只出现一次**：它的工作区被置顶时它在该分组里，否则（被置顶的）它才单独成行。
- 单独成行的置顶会话显示 `工作区名 · 标题`。
- **标题过长时，鼠标悬停会走马灯**：以恒定速度横向爬出被截断的内容，移开后立刻回到起点。
  这与官方会话行的显示方式一致（同一套常量与边缘渐隐），溢出不足 8px 的不动，避免抖动；
  系统开了「减少动态效果」时直接跳到末尾而不做动画。
- 会话在等你处理（授权、计划评审、回答）时显示琥珀色状态点，与官方侧栏一致。
- 归档、空白（New Session）与子代理会话都不显示；暂未加载的工作区/会话只是暂不显示，**不会丢掉置顶**。
- **两级折叠**，都按浏览器记住、刷新后保持：
  - 整个置顶区：折叠箭头在**标题右侧**，折叠后只留一行并显示条目总数；
  - 单个项目：点行折叠，折叠后显示该项目会话数。

### 行样式与官方一致

项目行与会话行**逐项对齐官方工作区行的数值**，所以两者像同一个列表而不是两个：

| | 项目行 | 会话行 | 官方 |
| --- | --- | --- | --- |
| 行高 | 34px | 32px | 34 / 32 |
| 圆角 | 8px | 8px | 8px |
| 标题字号 | 14px | 14px | 14px |
| 悬停按钮 | 16×16，间距 10px | 同左 | 同左 |

- 前置图标槽与官方同构：项目行有一个文件夹槽 + 一个箭头槽（都在 DOM 里，用 `display` 切换），
  **悬停时才把文件夹换成箭头**，静止时不显示箭头。
- 项目包含你正在看的会话时，文件夹变主题色 —— 与官方完全一致（实测同色值）。
- 悬停按钮条默认 `display:none`，悬停才出现；尾部时间也会在悬停时隐藏，与官方相同。

### 右侧按钮

行右侧**没有叉叉**，也没有常驻的展开箭头 —— 状态变更都在菜单里，与官方行的做法一致。

| 行 | 右侧按钮 | 菜单内容 |
| --- | --- | --- |
| 项目 | `…` 菜单、新建会话 | 官方的重命名 / 删除工作区 **+** 插件的置顶、编辑多文件夹、在资源管理器中打开、复制路径、新建会话 |
| 会话 | `…` 菜单、归档、取消置顶 | 官方的重命名 / 分叉 / 归档 **+** 插件的取消置顶、**复制会话引用**、导出 Markdown、打开所在目录 |

菜单**浮层本身就是官方的**（`Menu` 从共享层转发官方组件，共享层不再自绘），
面板菜单与官方行菜单用同一个组件、同一套样式，实测两边的浮层与行的
背景 / 圆角 / 阴影 / 内边距 / 行高 / 字号 / z-index 逐项相同。

菜单条目来自**同一份清单**（`row-menu.ts`），面板与注入到官方菜单的那几项因此不会不一致；
差异只有一处：面板的置顶行显示「取消置顶 / 取消置顶会话」，因为面板里列出的本来就是已置顶的项。

**每一行都有图标，且用的是官方那一套** —— 项目菜单、置顶区的两个菜单、以及注入官方会话菜单的三行，
全都从 `row-menu.ts` 这一份清单派生（`pluginProjectRows` / `pluginSessionRows`），
所以不会出现"某个表面忘了加图标"这种不一致。 实现上是**直接转发官方组件**（`packages/ui` 里再导出），
而不是把官方素材抄进我们自己的图标集 —— 抄一份会漂移：官方哪天改了图标，我们那份不会跟着变，
而"跟旁边那行长得一样"正是这件事的目的。（本地图标集**零新增**：此前为未读标记加过一个 dot，
随该功能一并删掉了。）

> 导入官方图标要用 `...Regular` 变体。裸名（如 `IconPinOutline`）**只存在于类型声明里**，
> 运行时是 `undefined`，会以 React #130「Element type is invalid」的形式炸掉，而不是报找不到导入。

图标尺寸按官方实测值对齐，而不是估的：

| 位置 | 尺寸 |
| --- | --- |
| 行内 `…` 菜单按钮（项目行与会话行都有） | 16 |
| 项目行「新建会话」 | 16 |
| 会话行「归档」「取消置顶」 | 14 |
| 菜单里的行图标 | 14（容器 16×16） |

菜单里每行的文字左边缘因此全部落在同一像素位置（实测 7 行都是 51px）。

### 官方项目行菜单里的追加项

官方项目行（工作区行）的 `…` 菜单**没有槽位**，所以本插件的行是**注入**进去的。
官方 `Menu` 用 React 合成事件判断"指针离开了菜单"，而这**只在同一个 React 树里成立** ——
注入的行是那个 list 的 DOM 子节点，却是另一个 React root 的 React 子节点，
指针移上去会被判成"离开了"，菜单 200ms 后自己关闭（实测：只有官方 2 行时一直开着，
加上注入的行就只在 221ms 后关闭，指针全程静止）。

`menu-pointer-guard.ts` 兜住了这个信号：在捕获阶段拦截 `pointerout` / `pointerleave`，
当且仅当**本插件正在装饰该菜单**且**指针去往该行或其菜单之内**时吞掉它。
判定区域是**行 ∪ 菜单的并集** —— 因为触发关闭的那次事件目的地是行的按钮条
（触发按钮与菜单之间那 4px 过渡带，属于行自己的 padding）。
指针移到别处时照旧放行，菜单仍可正常关闭。

> 这是针对主机实现细节的兼容措施，不是公开接口，所以单独隔离在一个模块里并用测试锁住：
> 官方哪天给这个菜单开了槽位，整个模块可以删掉。

### 行菜单的打开 / 关闭

行菜单是**点击**打开的，关闭方式是**点击别处 / Escape / 选中某一项**。

它不会因为鼠标离开就关闭 —— 菜单浮层开在行下方、与触发按钮之间隔着 4px 的空隙
（那是行自己的内边距，既不属于按钮也不属于菜单），"指针离开即关闭"会让手在往下移动时把菜单弄没。
菜单打开期间，该行会保持高亮、按钮保持显示，这样你能看出菜单属于哪一行。

置顶区是**视图**：它不重排官方列表、不写官方排序账本，取消置顶也不影响官方顺序。
它作为一个整体块排在官方列表前面 —— 官方拖拽排序是按 **id** 计算的（`next.indexOf(target.id)`），
不依赖子元素位置，所以这块面板不会干扰官方行的排序。

注意：官方分组自身默认只显示前 5 个会话（其余要「展开」），而置顶区**不做这个截断** ——
这是有意的：置顶的项目就是"我要看全部"的意思。

## 行菜单

官方自己已经提供：置顶、重命名、分叉、归档、设置归档过滤。
本插件只**追加**官方没有的那些，并可在设置里逐项关掉。

**项目（工作区）行** —— 追加到官方 `…` 菜单里：

- 置顶项目 / 取消置顶
- 编辑多文件夹…
- 在资源管理器中打开
- 复制路径
- 新建会话

官方原有的「重命名」「删除工作区」保持不动。

**会话行** —— 通过官方 slot `sidebar.workspaces.session.menu.item` 注册，排在官方行之后：

- 复制会话引用
- 导出为 Markdown
- 打开所在目录

### 复制会话引用

会话菜单里的「复制会话引用」把该会话的**规范引用**放进剪贴板：

```
@[重构 workspace-plus 置顶区域](dsh-session:InNlc3Npb24tODYwZWNiOWEtMGI5Ni00MDdjLTlhMTktNWMxNjZkMDJhZDQ2Ig)
```

粘到输入框即可 `@` 到那个会话 —— 这正是 DSH 自己的会话引用格式（`dsh-session:` +
id 的 JSON 经 base64url），label 只是显示用，宿主从 URI 解析 id。

编码实现在**共享层** `packages/runtime/src/client.ts`，与 host 侧同名导出成为一对
（host 走官方实现，client 因为浏览器没有 `Buffer` 而必须自带）。两者的一致性由
`packages/runtime/test/session-reference-client.test.ts` 逐字节比对官方实现来保证 ——
这类比对只能放在 `packages/` 下，因为插件被契约检查禁止直接 import `@deepseek-ai/*`。

## 多文件夹工作区

1. 点「添加工作区」弹本插件窗口
2. 点「添加文件夹」才打开访达 / 系统选择器，每次加一个目录
3. 第一个文件夹默认是主仓；可随时改。主仓是官方 workspace、会话 cwd 和 workspace-write 范围
4. 其它文件夹仍算工作区范围（可读、可协调），写文件走工具拒绝后再申请放行
5. 绑定写进 `~/.dsh/workspace-plus/bindings.json`，并注入系统提示：列出全部文件夹，并说明可写范围只跟主仓
6. 之后通过项目行菜单的「编辑多文件夹…」改名称、文件夹和主仓
7. 用官方「删除工作区」删掉工作区后，**对应的绑定会在下次连接时自动清理** ——
   否则重新添加同一目录会静默把旧的多文件夹配置带回来

**接入方式**：占用官方两个目录选择 hole（`sidebar.workspaces.directoryFlow` 与
`conversation.hero.workspace.directoryFlow`），以低于官方 picker 后端的 priority 接管。
官方仍负责「添加工作区」入口的显隐、busy 态、失败重试对话框与「重新选择」；
插件只替换 `open` 到拿到路径之间的交互。**因此没有任何 `pickDirectory` / `workspaces.create` 猴补。**

**不做永久删除。** 工作区只提供官方的「删除工作区」（从列表移除），不删除磁盘目录；
会话只提供官方归档，不提供删除磁盘记录。

## 导出会话

会话行菜单选择「导出为 Markdown」，下载以会话标题命名的 UTF-8 `.md` 文件。

- 从宿主读取完整会话日志，无需先打开会话或滚动加载历史；包含压缩前的对话与分叉继承的历史。
- 按顺序保留全部用户正文、助手正文和代码块，附会话 ID、工作目录与时间。
- 工具请求、执行记录和结果合并为一项，相邻工具调用收进折叠区；保留名称、关键参数、
  输出摘要与失败状态。长输出保留首尾并明确标注截断，未记录结果的调用单独标记。
- 省略思考过程、系统提示与插件注入上下文、用量、重复流式片段以及模型专用的压缩替换副本。
- 图片等附件保留名称、类型和引用信息，不把二进制数据嵌入 Markdown。
- 进行中的会话导出已进入会话日志的快照，已记录的中断回复保留并标记；尚未入日志的生成片段、
  未发送的草稿和排队输入不在范围内。未闭合的代码围栏会在消息边界补齐并注明，避免影响后续对话排版。

导出只读取会话，不恢复代理、改写日志或改变会话状态。读取失败会报错，不会下载缺失历史的空文件。

## 设置

每一项追加都能在 DSH 侧栏插件管理页的本插件的配置里单独关掉。
置顶区本身也有开关。

## 使用

```sh
dsh plugin --profile web add ./plugins/dsh-workspace-plus
```

装完**重启 DSH web**。

## 布局

| Half | Source | 做什么 |
| --- | --- | --- |
| node | `src/index.ts` | 采纳文件夹、绑定存储、系统提示、`/dsh-workspace-plus/*`（工作区置顶、绑定、打开目录、导出） |
| browser | `src/client/index.tsx` | 置顶区、官方行菜单追加、目录选择、绑定窗口 |

实现的几个要点（都依赖官方公开契约，不猜内部实现）：

- **置顶区挂载点**：官方 `sidebar.workspaces` 是 single slot，
  官方浏览器内部是 `sectionHeader`（工作区标题，不滚动）+ `listArea`（flex:1），
  滚动容器是其中的 `bhn1Oq_list`。置顶区挂在**这个滚动容器的第一个子节点**上，
  于是天然位于标题下方、随列表滚动，且官方 header 一个字节都不动。
- **绝不挂进搜索结果树**：搜索激活时官方把树整个换成 `aria-label="搜索结果"` 的另一棵树，
  并随每次按键重建 —— 挂在那里会被直接抹掉。所以只接受 `aria-label` 为「会话 / Sessions」的浏览树；
  未知的树一律不接管。
- **行标识**：用官方 `data-row-key`（`workspace:<id>` / `session:<id>`）与
  `data-slot`，**不再**扫描 React fiber，也不依赖会随构建变化的哈希 class。
- **会话菜单**：注册进官方 slot，用官方 `MenuItemButton` 渲染。
- **项目菜单**：官方没有对应 slot，所以监听它打开、把本插件的行 portal 进去，
  同样用官方 `MenuItemButton`，从而共享官方列表的键盘遍历与收起行为。
- **多文件夹接入**：占官方 `directoryFlow` hole（priority 低于官方 picker 后端），
  不再猴补 `pickDirectory` / `workspaces.create`。对话框只挂一份（`shell.overlay`），
  hole 与项目行菜单两个入口共用它。
- **真实系统选择器**：优先用 `globalThis.__DSH_DIRECTORY_PICKER__`（DSH-Desktop 的桥），
  退回 `uiWorkspace.pickDirectory()`；与官方 native picker 的选择顺序一致。

## 数据与迁移

- **工作区置顶**由本插件管：宿主写在 `~/.dsh/workspace-plus/pins.json`（遵循 `DSH_HOME`），
  按单条操作保存，失败会重试，仅在宿主确认后提示成功。
- **会话置顶**由 DSH 管：`~/.dsh/storages/workspace.json` 的 `pinnedSessionIds`。
  旧版本存在本插件 `pins.json` 里的会话置顶会在首次加载时**逐个写入官方注册表**，
  全部成功后才清掉旧记录 —— 中途失败会保留并下次重试，不会丢置顶。
- localStorage（`dsh-workspace-plus:v3`）只保留工作区置顶缓存、菜单开关与置顶区折叠状态。
- 插件 HTTP 路由复用 DSH Connection 的 Host/Origin 与浏览器 Cookie 认证。
- 从 `dsh-multi-repo` 升级：首次加载会把 `~/.dsh/multi-repo/projects.json` 复制成新存储，旧文件保留不动。

## 相比旧版删掉了什么

旧版为绕过 DSH 当时的缺口做过一些补丁，0.1.7 已不需要，故一并移除：

- **React fiber 扫描**识别行身份 → 换成官方 `data-row-key`。
- **猴补** `workspaces.create` / `uiWorkspace.pickDirectory` → 换成占用官方 `directoryFlow` hole。
- **改写官方 tree 顺序**实现置顶 → 换成独立置顶区（不再和官方排序账本打架）。
- **冷会话标题补齐**与**会话复活修复**（0.1.5 时代的补丁）→ 删除。
